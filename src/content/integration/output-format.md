# 输出格式、分隔符与多码拼接

“读到了”不等于“系统能正确用”。输出格式要在联调前约定好，并写进接口文档。

## 一、先定报文结构

推荐固定字段顺序：

```text
状态|工位|时间戳|码1|码2|校验
```

例如：

```text
OK|ST03|2026-10-18T14:02:11|CODE-A|CODE-B|*
```

字段顺序固定，解析才稳定。

## 二、分隔符选择

| 分隔符 | 优点 | 风险 |
| --- | --- | --- |
| 逗号 | 通用 | 码内容可能含逗号 |
| 竖线 | 可读性好 | 码内容可能含竖线 |
| Tab | 少见 | 部分系统不支持 |
| JSON | 结构清晰 | 解析成本略高 |

如果码内容可能包含分隔符，要么转义，要么用 JSON。

## 三、多码拼接

- 固定顺序：按 ROI 区域编号排序。
- 按内容排序：适合码本身有规则。
- 不去重：保留全部。
- 去重：同一码在时间窗内只输出一次。

多码时一定要告诉下游“哪个码对应哪个位置”，否则追溯会错。

## 四、空结果与失败

必须定义：

- 读码失败输出什么
- 超时输出什么
- 多码只读到部分时输出什么
- 是否带错误码

不要用空字符串同时表示“失败”和“没有码”。

## 五、编码与转义

- 统一 UTF-8。
- 码内容含换行、分隔符时做转义。
- 文件名与报文分开处理。
- 时间戳统一时区。
