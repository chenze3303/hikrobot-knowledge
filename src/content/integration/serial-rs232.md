# RS232 / RS485 串口通讯

串口通讯看似简单，但接线和参数错一个就会“完全没反应”。

## 一、先确认物理层

| 类型 | 特点 | 距离 |
| --- | --- | --- |
| RS232 | 点对点，电平较高 | 短，通常十几米内 |
| RS485 | 差分，可多点 | 较长，需终端电阻 |

读码器支持哪种接口以型号为准。不要直接把 RS232 接到 RS485 差分端。

## 二、接线

RS232 最少需要：

```text
TXD → RXD
RXD → TXD
GND → GND
```

注意交叉连接：设备的 TX 接对方的 RX。

RS485 需要 A/B 差分线，总线两端加终端电阻，避免星形布线。

## 三、串口参数

必须一致：

- 波特率（如 9600、19200、115200）
- 数据位（通常 8）
- 停止位（通常 1）
- 校验位（None/Even/Odd）
- 流控（通常关闭）

## 四、协议与输出

- 触发命令
- 结果前缀/后缀
- 结束符
- 超时
- 多码顺序

建议先用串口助手手工发送触发命令，确认有返回，再接入 PLC。

## 五、常见问题

| 现象 | 排查 |
| --- | --- |
| 完全无返回 | TX/RX 接反、GND 未接、参数不一致 |
| 乱码 | 波特率/校验位不一致、编码错误 |
| 偶尔丢数据 | 线缆过长、干扰、无屏蔽 |
| 只能收不能发 | 流控或方向控制问题 |
| 多设备冲突 | RS485 地址或总线冲突 |

## 六、现场建议

- 使用屏蔽双绞线。
- 远离变频器和大功率线缆。
- 接头固定，防止松动。
- 记录每台设备的串口参数。
- 长距离优先 RS485，并加终端电阻。
