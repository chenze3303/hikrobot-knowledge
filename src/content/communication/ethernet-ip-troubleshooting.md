# EtherNet/IP 通讯排查（含汇川 PLC）

EtherNet/IP 与 Profinet 的排查思路接近，但有两个自己的坑：输入输出地址域必须一样大，以及第三方 PLC（尤其汇川）在功能位映射上的差异。

## 一、无法建立通讯

### 检查 PLC 端配置

- EDS 文件是否导入成功，并检查设备型号 IDXXXX 是否正确。
- 如果是汇川等其他品牌 PLC，读码器控制、状态和结果区域映射的寄存器地址是否没有冲突。
- PLC 地址是否与设备地址在同一个网段内。
- 保存好全部设置后是否重新下载至 PLC 内部。

### 检查相机端配置

- 相机是否是工作模式。
- 检查固件版本，最好使用最新版本，因为之前旧版连接汇川 PLC 可能存在问题。
- 是否在通讯配置中打开 EIP 协议使能。
- 输入输出地址域大小是否相同【注意单位是 Byte】：如果输入设置成 100，则输出也必须是 100。
- PLC 中物理地址是否有冲突，或者地址设置过大超过实际物理地址：可以更换地址，或者重新新建项目进行验证。
- 硬件连接：PLC 和读码器设备需要连接在同一个交换机网段内，相互能够 ping 通。

> 输入和输出地址域必须等长，这是 EIP 与 Profinet 组态习惯最不一样的一点，两侧都要按 Byte 核对一遍。

## 二、通讯建立后无法传输数据 / 没有条码结果

- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。
- PLC 中物理地址是否有冲突，可以更换地址或者重新新建项目进行验证。

## 三、通讯建立后无法正常触发

- 如果使用 PLC 控制状态位进行触发，相机配置的触发源需要选择「软触发」。
- 如果使用管脚硬触发，相机配置的触发源需要选择对应的「管脚几触发」。
- 如果是 IDMVS 连着相机，相机是否打开采集 / 取流；如果 IDMVS 没有连着，则检查相机是否打开自动工作使能。
- 检查设备用户参数是否保存。

## 四、触发之后没有状态位返回

- 如果使用管脚进行硬触发，固定式读码器没有状态区域的任何反馈，且不可随意修改控制区域的控制位（否则相机会自动跳转成软触发）。
- 如果使用管脚进行硬触发（扣动扳机），巴枪读到码的话，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 如果使用狂扫模式（非触发模式）进行读码，状态区域也不会有任何反馈。

## 五、状态区域最后一位 clear error 总报错

- IDMVS 通讯配置中的通讯超时时间可以设长（默认 10s）。
- 主从融合需要时间。
- 轮询需要时间。
- 一次触发多帧拍摄需要时间。
- IDMVS 配置完成后，连接相机时需要打开取流。

### 汇川 PLC 无法通过控制位置位清错

- 现象：状态区域最后一位报错位，无法通过控制位进行置位清错。
- 原因：客户 PLC 程序中给控制位的清错位（clear error）添加了变量「标签」（一个感叹号标志）。
- 处理：去掉标签即可正常置位清错。

## 六、结果区域条码错乱

- 勾选读码器通讯配置中的「结果字节交换使能」。
