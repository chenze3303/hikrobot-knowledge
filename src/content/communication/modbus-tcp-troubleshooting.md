# Modbus TCP 通讯排查（客户端 / 服务器）

Modbus TCP 有两种接法：读码器做客户端去连 Modbus Slave，或者读码器做服务器等 Modbus Poll 来连。两种角色的排查顺序不同，先确认自己在哪一种。

## 一、读码器做客户端，连接 Modbus Slave

### 无法正常连上通讯

**检查 IDMVS 里的相机通讯配置**

- 相机是否是工作模式。
- Modbus 通讯是否是客户端。
- Modbus 服务器 IP 是否是 PC 的 IP（如果是连接 PLC，则填入 PLC 的 IP）。
- 检查固件版本，不是太老即可，22 年之后即可。

**检查 Modbus Slave 通讯助手配置**

- 检查助手内的本地 PC 的 IP 是否正确。
- 选择的是否是 Modbus TCP 配置。
- 检查端口号是否是 502。
- 检查站号 Slave ID，如果 255 不行可以尝试 0。
- PC 防火墙是否全部关闭，且关闭其他杀毒软件。

> 如果一直连不上该助手，或者该助手总报错，可以使用其他通讯助手，例如 Modbus Client Tester，可以找总部技术同事获取。

### 能够正常触发但结果区域没有数据

- 将助手内的寄存器大小 Quantity 设大，需要大于读码器三个区域的总共大小。
- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。

## 二、读码器做服务器，连接 Modbus Poll

### 无法正常连上通讯

**检查 IDMVS 里的相机通讯配置**

- 相机是否是工作模式。
- Modbus 通讯是否是服务端。
- 检查固件版本，不是太老即可，22 年之后即可。

**检查 Modbus Poll 通讯助手配置**

- 选择的是否是 Modbus TCP 配置。
- 检查需要连接的服务器 IP 是否是读码器 IP。
- 检查端口号是否是 502。
- PC 防火墙是否全部关闭，且关闭其他杀毒软件。

### 无法修改控制区域和状态区域的偏移地址

- 读码器做 Modbus 服务器时，无法自行修改控制和状态区域的偏移地址，因为该寄存器存放在读码器内部，已写死。

### 能够正常触发但结果区域没有数据

- 将助手内的寄存器大小 Quantity 设大，需要大于读码器三个区域的总共大小。
- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。

## 三、通讯建立后无法正常触发（两种角色通用）

- 如果使用 PLC 控制状态位进行触发，相机配置的触发源需要选择「软触发」。
- 如果使用管脚硬触发，相机配置的触发源需要选择对应的「管脚几触发」。
- 如果是 IDMVS 连着相机，相机是否打开采集 / 取流；如果 IDMVS 没有连着，则检查相机是否打开自动工作使能。
- 检查设备用户参数是否保存。

## 四、触发之后没有状态位返回

- 如果使用管脚进行硬触发，固定式读码器没有状态区域的任何反馈，且不可随意修改控制区域的控制位（否则相机会自动跳转成软触发）。
- 如果使用管脚进行硬触发（扣动扳机），巴枪读到码的话，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 如果使用狂扫模式（非触发模式）进行读码，状态区域也不会有任何反馈。

## 五、状态区域最后一位 clear error 总报错

- IDMVS 通讯配置中的通讯超时时间可以设长（默认 10s）。
- 主从融合需要时间。
- 轮询需要时间。
- 一次触发多帧拍摄需要时间。
- IDMVS 配置完成后，连接相机时需要打开取流。

## 六、结果区域条码错乱

- 勾选读码器通讯配置中的「结果字节交换使能」。
