# PLC 通讯寄存器与状态位基础

不管接的是 Profinet、MC & SLMP、Modbus TCP、EtherNet/IP 还是 Fins，读码器与 PLC 之间的数据都落在三个区域里。先把这几个概念对齐，具体协议的排查就是填空题。

## 一、位、字节与字

- 1 个字 Word = 2 个字节 Byte = 16 个位 Bit。

| 单位 | 换算 |
| --- | --- |
| 1 Word | 2 Byte |
| 2 Byte | 16 Bit |

组态时最容易出错的地方，就是 PLC 侧按「字」算、IDMVS 侧按「字节」算。看到地址域大小对不上，先确认双方的单位。

## 二、三个区域

| 区域 | 方向 | 作用 |
| --- | --- | --- |
| 控制区域 | PLC → 读码器 | 触发、清错等功能位 |
| 状态区域 | 读码器 → PLC | 报错、完成等状态位 |
| 结果区域 | 读码器 → PLC | 条码长度 + 条码内容 |

- 控制区域和状态区域通常占用一个寄存器大小（1 个字或者 1 个字节）【除 EIP 通讯不同】。
- 控制区域和状态区域最后一位分别是清错 clear error 和报错 general fault【除 EIP 通讯不同】。

> EIP 通讯会把控制区域和状态区域各个「功能位」映射到不同寄存器的不同位，这个映射由客户的 PLC 决定，所以 EIP 的位定义不能照搬其他协议。

## 三、各协议用的组态文件

- Profinet 通讯需要安装 GSD 文件。
- EIP 通讯需要安装 EDS 文件。

导入的是哪一份文件，要和 PLC 软件里的设备型号对上；Step7 等老款西门子软件可能需要专用的 GSD 文件。

## 四、结果区域为什么会少一位或错乱

- 结果区域实际由「条码长度 + 条码内容」组成，所以结果区域实际大小要多一个字节（寄存器）。
- 结果区域占用的寄存器大小一般都可自行配置，一个字节通常存有一个 ASCII 码内容。
- 格式化输出为空时，结果区不会有条码内容，需要加上 `<code_content>`。
- 条码内容错乱时，勾选读码器通讯配置中的「结果字节交换使能」。

## 五、触发与状态反馈

- 用 PLC 控制状态位触发，相机触发源必须选「软触发」；用管脚硬触发，触发源必须选对应的「管脚几触发」。
- 固定式读码器用管脚硬触发时，状态区域没有任何反馈，且不要随意修改控制区域的控制位，否则相机会自动跳成软触发。
- 巴枪用管脚硬触发（扣动扳机）读到码时，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 使用狂扫模式（非触发模式）读码时，状态区域同样没有任何反馈。
- IDMVS 连着相机时要打开采集 / 取流；IDMVS 没连着时，检查相机是否打开自动工作使能。
- 状态区域最后一位 clear error 反复报错时，可把通讯超时时间设长（默认 10s），并留出主从融合、轮询、单次触发多帧拍摄的时间。
