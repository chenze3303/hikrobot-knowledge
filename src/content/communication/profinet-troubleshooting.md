# Profinet 通讯排查（西门子）

Profinet 的问题大多集中在三处：组态没有下载对、设备名称或 IP 对不上、结果区字节数不一致。按「先能连上，再能触发，最后看数据」的顺序排查，比反复改参数更快。

## 一、无法建立通讯

### 检查 PLC 端配置（博图）

- GSD 文件是否导入成功。
- 选用的读码器设备组态型号 IDXXXX 是否正确。
- 结果区域字节大小与 IDMVS 中配置是否一致：例如 IDMVS 设置为 64 字节，则地址域也需要设置 64 字节大小。
- 组态中的设备名称是否对应成功：如果是中文或带有特殊字符，需要使用转换后的名称。
- 组态中的 IP 地址需要与 IDMVS 中读码器地址不一致，但需要在同一网段内。
- PLC 组态地址是否与设备组态地址在同一个网段内。
- 保存好全部设置后，是否重新下载至 PLC 内部。

> Step7 等老款西门子软件可能需要使用特定的 GSD 文件，可找总部技术同事获取。

### 检查相机端配置

- 相机是否是工作模式。
- 检查固件版本，不是太老即可，22 年之后即可。
- 是否在通讯配置中打开 Profinet 协议使能。
- 数据结果字节大小是否与 PLC 软件配置中一致。
- PLC 中物理地址是否有冲突，或者地址设置过大超过实际物理地址：可以更换地址，或者重新新建项目进行验证。

### 硬件连接

- PLC 和读码器设备需要连接在同一个交换机网段内，相互能够 ping 通。

## 二、通讯建立后无法传输数据 / 没有条码结果

- 检查读码器组态的 IP 地址，需要与 IDMVS 中读码器地址不一致。
- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。
- PLC 中物理地址是否有冲突，可以更换地址或者重新新建项目进行验证。

> 如果结果区域第一位被截取，注意结果区域实际由「条码长度 + 条码内容」组成，所以结果区域实际大小要多一个字节（寄存器）。

## 三、通讯建立后无法正常触发

- 如果使用 PLC 控制状态位进行触发，相机配置的触发源需要选择「软触发」。
- 如果使用管脚硬触发，相机配置的触发源需要选择对应的「管脚几触发」。
- 如果是 IDMVS 连着相机，相机是否打开采集 / 取流；如果 IDMVS 没有连着，则检查相机是否打开自动工作使能。
- 检查设备用户参数是否保存。

## 四、触发之后没有状态位返回

- 如果使用管脚进行硬触发，固定式读码器没有状态区域的任何反馈，且不可随意修改控制区域的控制位（否则相机会自动跳转成软触发）。
- 如果使用管脚进行硬触发（扣动扳机），巴枪读到码的话，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 如果使用狂扫模式（非触发模式）进行读码，状态区域也不会有任何反馈。

## 五、状态区域最后一位 clear error 总报错

- IDMVS 通讯配置中，PN 通讯超时时间可以设长（默认 10s）。
- 主从融合需要时间。
- 轮询需要时间。
- 一次触发多帧拍摄需要时间。
- IDMVS 配置完成后，连接相机时需要打开取流。

## 六、结果区域条码错乱

- 勾选读码器通讯配置中的「结果字节交换使能」。
