# Fins 通讯排查（欧姆龙）

Fins 是欧姆龙 PLC 的原生以太网协议。相机作客户端，PLC 作服务器。除了常规的 IP、端口与地址配置，还要特别确认网口位置。

## 一、无法建立通讯

### 相机端（作客户端）配置

- 确定该设备是否支持 Fins 通讯协议；检查相机固件版本，不是太老即可，22 年之后即可。
- 相机是否是工作模式。
- 检查 Fins 服务器 IP 与 PLC 的是否对应。
- 检查 Fins 服务器端口号。
- 检查控制、状态、结果区域地址配置是否与实际 PLC 物理寄存器地址冲突。

### PLC 端（作服务器）配置

- 检查 PLC IP / 子网掩码 / 路由器 IP。
- 检查以太网配置和寄存器配置，详细见操作文档。
- 检查以太网配置中的端口号是否可用或者被占用。
- 配置好的程序是否完全写入 PLC。
- 相机需要和 PLC 在同一个交换机网段中，且必须使用欧姆龙 PLC 的「2 号网口」，端口 1 不支持 Fins。

> 端口 1 不支持 Fins，排查时先确认网线接的是 2 号网口，再看 IP 与端口配置。

## 二、通讯建立后无法传输数据 / 没有条码结果

- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。
- PLC 中物理地址是否有冲突，可以更换地址或者重新新建项目进行验证。

## 三、通讯建立后无法正常触发

- 如果使用 PLC 控制状态位进行触发，相机配置的触发源需要选择「软触发」。
- 如果使用管脚硬触发，相机配置的触发源需要选择对应的「管脚几触发」。
- 如果是 IDMVS 连着相机，相机是否打开采集 / 取流；如果 IDMVS 没有连着，则检查相机是否打开自动工作使能。
- 检查设备用户参数是否保存。

## 四、触发之后没有状态位返回

- 如果使用管脚进行硬触发，固定式读码器没有状态区域的任何反馈，且不可随意修改控制区域的控制位（否则相机会自动跳转成软触发）。
- 如果使用管脚进行硬触发（扣动扳机），巴枪读到码的话，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 如果使用狂扫模式（非触发模式）进行读码，状态区域也不会有任何反馈。

## 五、状态区域最后一位 clear error 总报错

- IDMVS 通讯配置中的通讯超时时间可以设长（默认 10s）。
- 主从融合需要时间。
- 轮询需要时间。
- 一次触发多帧拍摄需要时间。
- IDMVS 配置完成后，连接相机时需要打开取流。

## 六、结果区域条码错乱

- 勾选读码器通讯配置中的「结果字节交换使能」。
