# MC & SLMP 通讯排查（三菱）

MC 与 SLMP 是三菱 PLC 上最常见的两种以太网通讯方式。排查时先确认帧类型与数据代码是否配对，再看地址、端口和保活时间。

## 一、无法建立通讯

### PLC 端（作服务器）配置

- 是否选上「允许 PLC run 中写入」配置选项：若不选，可能导致 PLC 在工作中无法更新配置。
- 重新下载配置后，三菱 PLC 需要重启，配置才可生效。
- 检查通讯数据代码：ASCII 还是二进制，需要与读码器配置对应。
- 检查 PLC IP / 子网掩码 / 路由器 IP。
- 以太网配置中需要选择 TCP 协议 → MC 协议或 SLMP。
- 检查以太网配置中的端口号是否可用或者被占用。
- 写入下载进 PLC 需要全选再执行下载。

### 相机端（作客户端）配置

- 确定该设备是否支持 MC 通讯协议；检查相机固件版本，不是太老即可，22 年之后即可。
- 相机是否是工作模式。
- 检查 MC 服务器 IP 与 PLC 的是否对应。
- 检查 MC 服务器端口号。
- 检查 MC 控制、状态、结果区域地址配置是否与实际 PLC 物理寄存器地址冲突。
- R / Q 系列 PLC 需要选择 3E 帧类型，FX3U 系列 PLC 选择 1E 帧类型。
- 帧类型配置中：ASCII 对应 PLC 的 ASCII 类型，BIN 对应二进制类型。
- 硬件连接：PLC 和读码器设备需要连接在同一个交换机网段内，相互能够 ping 通。

> R / Q 系列与 FX3U 用的帧类型不同，先确认 PLC 属于哪一系列，再选 3E 还是 1E。

## 二、通讯建立后无法传输数据 / 没有条码结果

- IDMVS 中相机端 → 数据处理 → 格式化输出是否为空，需要增加条码内容 `<code_content>`。
- PLC 中物理地址是否有冲突，可以更换地址或者重新新建项目进行验证。

## 三、PLC 重启后 MC 通讯无法立刻重连

- 进入控制 PLC 软件，进入网络模块设置 → 初始化界面，将默认的 600s 保活时间设置为 5s 或 10s 即可。
- 问题原因：三菱部分系列 PLC 默认端口从前连接的「保活时间」为 600s。

> 表现是 PLC 重启后读码器要等很久才恢复通讯。把保活时间从 600s 改成 5s 或 10s，重连会明显变快。

## 四、通讯建立后无法正常触发

- 如果使用 PLC 控制状态位进行触发，相机配置的触发源需要选择「软触发」。
- 如果使用管脚硬触发，相机配置的触发源需要选择对应的「管脚几触发」。
- 如果是 IDMVS 连着相机，相机是否打开采集 / 取流；如果 IDMVS 没有连着，则检查相机是否打开自动工作使能。
- 检查设备用户参数是否保存。

## 五、触发之后没有状态位返回

- 如果使用管脚进行硬触发，固定式读码器没有状态区域的任何反馈，且不可随意修改控制区域的控制位（否则相机会自动跳转成软触发）。
- 如果使用管脚进行硬触发（扣动扳机），巴枪读到码的话，状态区域会返回一个 200ms 的 Result OK 信号，其他状态位不会有反馈。
- 如果使用狂扫模式（非触发模式）进行读码，状态区域也不会有任何反馈。

## 六、状态区域最后一位 clear error 总报错

- IDMVS 通讯配置中的通讯超时时间可以设长（默认 10s）。
- 主从融合需要时间。
- 轮询需要时间。
- 一次触发多帧拍摄需要时间。
- IDMVS 配置完成后，连接相机时需要打开取流。

## 七、结果区域条码错乱

- 勾选读码器通讯配置中的「结果字节交换使能」。
