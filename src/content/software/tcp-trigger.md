# TCP / UDP 触发与结果输出

TCP 触发适合上位机统一控制节拍的场景。读码器作为 TCP 服务端，等待上位机发送触发字符串。

## 一、配置步骤

1. 打开 `I/O Control Settings → Input → Trigger Mode`。
2. 将 Trigger Mode 设为 On。
3. Trigger Source 选择 `TCP Start` 或 `UDP Start`。
4. 设置触发端口，常见示例为 `2001`。
5. 设置触发字符串，常见示例为 `start`。
6. 保存到设备。

> 端口和触发字符串只是示例，实际以当前型号手册为准。

## 二、联调

先用命令行确认链路：

```bash
# 发送触发字符串
printf 'start' | nc 192.168.1.10 2001
```

如果读码器有返回结果，再接入上位机。注意：

- 触发字符串要完全匹配，包括大小写。
- 每次触发后等待结果，不要无间隔连续发送。
- 设置合理的超时和重试。
- 网络断开后要能自动重连。

## 三、结果输出

常见输出项：

| 项目 | 说明 |
| --- | --- |
| 码内容 | 读取到的字符串 |
| 状态 | 成功/失败/超时 |
| 时间戳 | 触发或解码时间 |
| 工位号 | 多工位区分 |
| 图像 | 可选，通常配合 FTP |

开启“TCP 输出换行”后，每条结果末尾会追加换行符，便于上位机按行解析。

## 四、上位机伪代码

```python
import socket

with socket.create_connection(("192.168.1.10", 2001), timeout=3) as s:
    s.sendall(b"start")
    data = s.recv(4096)
    print(data.decode("utf-8", errors="ignore"))
```

生产代码还要加：

- 重连
- 超时
- 结果校验
- 日志
- 失败重试上限

## 五、常见问题

- **连不上**：IP、端口、防火墙、服务端是否监听。
- **触发无反应**：字符串不匹配、触发模式未保存、端口被占用。
- **结果粘包**：按换行或固定长度解析，不要假设一次 recv 就是一条。
- **偶发超时**：网络抖动、读码器忙、上位机发送过快。
- **多工位串结果**：用工位号或独立端口区分。
