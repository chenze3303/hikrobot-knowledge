# 网络不通与丢触发

网络问题分三层：物理链路、网络配置、应用报文。按层排查，比反复重启有效。

## 一、物理层

- 网口指示灯是否亮
- 网线是否损坏
- 交换机端口是否正常
- 供电是否稳定
- 是否使用了不合格的电源/线缆

## 二、网络配置

- IP 是否同网段
- 子网掩码是否正确
- 是否有多网卡冲突
- 是否有 DHCP 地址变化
- 防火墙是否放行

```bash
ping 192.168.1.10
arp -a
telnet 192.168.1.10 2001
```

## 三、应用层

- TCP 服务端是否监听
- 端口是否被占用
- 触发字符串是否匹配
- 是否按换行正确拆包
- 是否有超时与重连

## 四、丢触发的常见原因

| 原因 | 表现 | 处理 |
| --- | --- | --- |
| 光电抖动 | 偶发多触发/漏触发 | 加去抖、调整位置 |
| 发送过快 | 读码器忙，结果丢失 | 等结果或加队列 |
| 网络丢包 | 偶发超时 | 检查交换机、线缆 |
| 端口冲突 | 完全无响应 | 换端口 |
| 触发未保存 | 重启后失效 | 保存到设备 |

## 五、抓包与日志

- 在读码器侧记录触发计数和结果计数。
- 在上位机侧记录发送和接收日志。
- 必要时用 Wireshark 抓包，确认请求是否到达。
- 对比触发数与结果数，定位丢在哪一段。

## 六、长期稳定建议

- 固定 IP，不用 DHCP。
- 独立网段或 VLAN。
- 工业交换机，避免消费级交换机。
- 屏蔽线缆，远离干扰源。
- 上位机做重连与告警。
